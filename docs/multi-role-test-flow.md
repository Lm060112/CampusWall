# 多角色测试流程

## 测试账号准备

在 `users` 集合准备至少 4 个用户：

- `student`：普通学生
- `runner`：跑腿人员
- `merchant_staff`：运营/商家人员
- `admin`：管理员

每个账号都需要先在小程序登录一次，确保有 `_openid`。

## student 测试

- 可以浏览首页、发现、消息、我的。
- 可以发布帖子、评论、点赞、收藏。
- 可以举报帖子。
- 可以下单、查看自己的订单。
- 可以提交学生认证。
- 看不到管理后台。
- 调用管理接口应返回 `permission denied`。

## runner 测试

- 可以进入管理后台。
- 总览只能看到订单相关数据。
- 可以查看管理订单。
- 可以修改跑腿/订单状态。
- 不应看到用户、公告、认证、审核管理能力。

## merchant_staff 测试

- 可以进入管理后台。
- 可以查看订单。
- 可以管理商家和商品。
- 不应修改用户角色。
- 不应审核认证或处理举报。

## admin 测试

- 可以进入管理后台全部标签。
- 可以修改订单状态。
- 可以新增/编辑公告、商家、商品。
- 可以处理举报。
- 可以隐藏、恢复、删除帖子。
- 可以审核学生认证。
- 可以修改用户角色。
- 可以查看操作日志。

## 回归测试

- 切换角色后重新登录或重新编译，小程序显示应同步变化。
- 管理后台搜索、筛选结果应符合当前标签。
- 操作后总览数字应刷新。
- 错误场景应有 toast 提示，不应白屏。
