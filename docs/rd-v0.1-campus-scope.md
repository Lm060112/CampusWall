# 岛上小集 MVP V0.1 校区范围与业务边界 RD 摘要

## 1. 产品定位

对外定位：崇明陈家镇大学城校园生活服务入口 MVP。

对内定位：未来可扩展为崇明多校区校园经济运营平台。

## 2. 第一版市场策略

- 中华职业技术学院：最小真实订单试验场。
- 上海民远职业技术学院：九月新生入口与预运营市场。
- 上海外国语大学贤达经济人文学院：成熟混乱市场的整合切口。
- 上海交通大学：未来占位市场，暂不投入运营资源。

## 3. 核心字段原则

- `serviceAreaId`：服务市场区域，例如 `chongming_chenjia`。
- `institutionId`：学校主体。
- `campusId`：具体运营校区，是用户选择、订单归属和模块展示的核心。
- `visibleCampusIds`：内容或商家在哪些校区可见。
- `serviceCampusIds`：服务或商家实际支持哪些校区下单/履约。
- `operationStatus`：校区运营状态，例如 `active` / `pre_operation` / `reserved`。
- `enabledModules`：校区开放的模块。
- `roleScope`：管理员、骑手、商家、校园生活官等角色的权限范围。

## 5. 第一版正式开放

- 中华校内点单。
- 中华跑腿代取。
- 中华校外外卖轻订单。
- 各校区需求登记。
- 基础内容/公告/指南入口。
- 平台管理员后台处理订单和需求。

## 6. 第一版预登记开放

- 民远新生生活包意向。
- 校园生活官申请。
- 兼职需求。
- 二手电动车/自行车需求。
- 商家合作申请。

## 7. 第一版占位展示

- 交大专区。
- 完整代理中心。
- 完整二手交易市场。
- 微信支付。
- 商家自助后台。
- 自动分账。
- 会员系统。

## 8. 第一版不做

- 不接正式微信支付。
- 不做自动派单。
- 不开放商家自助后台。
- 不做完整代理中心。
- 不做完整二手交易市场。
- 不做自动分账。
- 不承诺全崇明区履约。
- 不使用学校官方口吻、校徽、官方合作等表达。

## 9. 订单和支付原则

- 开发环境可以保留模拟支付。
- 正式运营必须改为待人工确认付款。
- 用户不能自行把订单改成已付款。
- 订单必须固化 `campusId`。

## 10. 技术实现原则

- 先做配置层，不一次性重构全项目。
- 先前端最小校区选择，再做后端过滤。
- 先需求登记和轻订单，后支付和自动化。
- 每次 Codex 只允许改一个小任务，必须先看 diff，再测试，再 commit。
